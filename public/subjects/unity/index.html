Transform과 도구

1권 p.51, 55–62 · 2권 p.10

항목실제 효과주의
Position위치 변경부모가 있으면 Inspector 값은 부모 기준 로컬 좌표
Rotation회전각 변경Rotate(x,y,z)는 좌표 이동이 아니라 축을 중심으로 회전
Scale크기 배율 변경(3,3,3)은 각 축 3배. 부모 Scale도 자식 외형에 영향
Hand / View 도구Scene 편집 시점 이동오브젝트 이동이 아님
Move / Rotate / Scale선택 오브젝트 이동 / 회전 / 크기 변경기즈모의 축·핸들을 드래그
Rect 도구사각 핸들로 크기·배치 조작UI/2D에 특히 유용. 실제 기준점은 피벗·선택 상태에 영향
Transform 도구이동·회전·크기 핸들을 함께 제공1권의 복합 도구
Pivot / Center편집 기즈모를 실제 피벗 / 선택 대상의 중앙에 배치스크립트의 회전 원점을 자동으로 바꾸는 설정이 아님
Local / Global편집 핸들의 축을 오브젝트 기준 / 월드 기준으로 표시Rotate·Translate의 Space 인수와 별도로 구분

Pivot은 선택한 오브젝트의 실제 피벗이고 Center는 선택 대상의 중앙입니다. 공식 기즈모 설명

지구와 달: 자전과 공전

2권 p.4–11

지구와 달에 각각 회전 스크립트만 붙이면 각자의 피벗 주위로 자전합니다. Hierarchy에서 달을 지구의 자식으로 만들고, 달을 지구 피벗에서 떨어진 위치에 두면 지구의 회전이 달의 월드 위치에도 반영되어 공전처럼 보입니다.

부모 이동·회전·크기 → 자식에 영향. 자식의 Transform만 바꾼다고 부모의 Transform이 바뀌지는 않습니다. 달이 회전축 위에 있으면 원을 그리는 공전이 보이지 않을 수 있습니다.

Prefab: 설정을 묶어 재사용

2권 p.12–15

같은 총알·아이템을 반복해서 쓸 때 유용합니다. 원본 Prefab을 바꾸면 연결된 인스턴스에 변경이 반영됩니다. 단, 인스턴스에서 해당 속성을 별도로 덮어쓴 Override가 있으면 그 값은 원본을 그대로 따르지 않을 수 있습니다.

파란색 아이콘은 강의자료의 식별 힌트입니다. 색만 외우기보다 원본 에셋 ↔ 씬의 인스턴스 관계를 이해하세요.

색상·투명도·태양의 표면

1권 p.64–67 · 3권 p.14–16 (캡처 확인)

색: Material 생성 → Base Map 색상 변경 → 오브젝트에 적용. 반투명: Transparent로 변경한 뒤 A(알파)를 조절합니다. Opaque 상태에서는 알파만 낮춰도 기대한 반투명 표현이 되지 않습니다. 알파의 표시 범위는 UI에 따라 달라도 낮을수록 투명해진다는 원리는 같습니다.

3권 p.16 화면의 Shader는 Unlit/Transparent입니다. 조명에 따른 명암 영향을 받지 않는 표면을 만들어 태양 이미지가 밝게 보이게 합니다. Unlit 자체가 주변 물체를 비추는 광원이 되는 것은 아닙니다. 캡처에서는 Sphere 아래에 Point Light를 둡니다. URP 프로젝트에서는 호환되는 Universal Render Pipeline/Unlit 계열을 사용하고 투명 옵션을 별도로 확인합니다.

05 · Input System 준비와 입력 읽기

Unity 6000.3.23f1 · 신형 입력 기준

이 정리본은 Input System 패키지의 Keyboard와 Mouse를 직접 읽는 방식으로 통일합니다. 에디터 버전과 패키지 버전은 별개이므로, Package Manager에서 프로젝트에 설치된 Input System 버전을 확인하세요.

준비 항목설정
패키지Window → Package Management → Package Manager → Unity Registry → Input System → Install (이미 설치되어 있으면 확인만)
활성화Edit → Project Settings → Player → Other Settings → Configuration → Active Input Handling → Input System Package (New)
코드 상단using UnityEngine;
using UnityEngine.InputSystem;
실행파일명과 클래스명을 맞춤 → 활성 오브젝트에 스크립트 부착 → Play → Game 창에 포커스
업데이트 방식아래 예제는 기본 Dynamic Update에서 Update()로 입력을 읽음

C#의 using은 타입 이름을 사용하기 위한 네임스페이스 선언입니다. 패키지 설치나 입력 활성화를 대신하지 않습니다. 설정 변경 후 에디터 재시작을 요청하면 재시작하세요.

두 using 선언의 역할

using UnityEngine;
using UnityEngine.InputSystem;

UnityEngine: MonoBehaviour, Transform, Time, Vector3, Rigidbody 등 Unity 기본 타입.
UnityEngine.InputSystem: Keyboard, Mouse 등 입력 장치 타입.

장치를 직접 읽는 이 예제에는 Input Actions 에셋이나 PlayerInput 컴포넌트가 필수는 아닙니다. Keyboard.current 또는 Mouse.current가 null일 수 있으므로 장치 존재를 확인합니다.

누른 순간 · 누르는 동안 · 뗀 순간

2권 p.21–23 · 3권 p.22–26

시점상태 속성용도
누른 순간wasPressedThisFrame한 번 회전, 한 칸 이동, 클릭당 크기 증가
누르고 있는 동안isPressed지속 이동·회전
뗀 순간wasReleasedThisFrame키나 버튼을 놓았을 때 한 번 처리

Update에서 이 속성을 조건으로 검사합니다. 누른 순간과 뗀 순간은 해당 입력 프레임에서, 유지 상태는 누르는 여러 프레임에서 true가 됩니다.

G · Rigidbody의 물리 수면 해제

3권 p.17 (이미지 속 코드)

같은 오브젝트에서 Rigidbody를 찾아 WakeUp을 호출합니다. RequireComponent는 부착 시 Rigidbody가 필요함을 선언합니다. null 검사도 넣었습니다. 매 프레임 깨우는 강의 예제의 목적을 재현하지만 물체를 움직이거나 계속 튕기게 하는 힘은 주지 않습니다.

파일명: KeepAwake.cs

전체 코드 · using 포함
using UnityEngine;

[RequireComponent(typeof(Rigidbody))]
public class KeepAwake : MonoBehaviour
{
    private Rigidbody body;

    void Awake()
    {
        body = GetComponent<Rigidbody>();
    }

    void Update()
    {
        if (body != null)
        {
            body.WakeUp();
        }
    }
}

물리 보충: 위 Transform 예제는 명령어 이해용입니다. 실제 Rigidbody 물체를 물리적으로 움직일 때는 FixedUpdate와 Rigidbody의 힘·이동 API를 검토해야 합니다. 바닥을 Transform으로 회전시키는 실습을 모든 물리 상황의 정답으로 일반화하지 마세요.
